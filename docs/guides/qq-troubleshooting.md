# QQ 桥启动与回复排查

## 重复启动与停止

本体按保存的 PID、精确的 `-m 模块 子命令` 参数片段与启动时间校验进程，
不以工作目录识别进程。解释器跳板或插件改变工作目录不应使运行状态消失。
启动与停止使用同一功能锁；停止会处理该功能所有仍可确认身份的历史运行记录及其子进程。
停止失败保留记录以便重试，不扫描或强杀未登记进程。
QQ 桥自身还持有 `data/bridge.lock` 操作系统锁，防止同一安装被终端重复启动；进程退出自动释放，勿删除正在使用的锁文件。

旧版本遗留、但没有运行记录的实例需要手动确认来源后关闭。仅升级文件不会自动清理正在运行的旧程序。

## 回复格式

支持完整的 JSON 代码围栏和已闭合的 think 标签，仍校验角色及动作。
结构化回复和纯文本兼容均失败时，诊断保留首次结构化错误与兼容错误。
解析失败时将首次错误和模型正文保存到本机 `backend/data/qq-parse-fail/`，最多保留 20 份，每份原文最多 64 KiB。
这包含私人对话内容，不进入普通日志或 API，不上传；排查后可手动删除。原始用户消息仍留在本地会话中。
没有可用表情候选时提示只生成文字；不会以随机图片替换不存在的表情。

## 私聊授权与群聊触发

- `owner.whitelist_bypass`：只允许管理员私聊绕过私聊名单。
- `owner.mention_bypass`：独立的群聊免 @ 开关，默认关闭；仍需群在白名单中。
- 普通模式固定关闭群聊免 @，专家模式可明确开启。
- 原有叫角色名字的触发方式保留，因此“需要 @”也允许有效角色名字唤起。

普通模式修改顶层群／私聊名单时，只更新当前选中的账号，不扩展其他账号权限。
同一次保存若明确提交账号级名单，则以账号名单为准，空名单也生效。
