- 当前源码检查拒绝重新跟踪上述路径；构建后另查禁止附带的文件。此检查针对已知路径，不等于全库素材或供应链法律审计。
- Git 历史未改写，旧提交仍可能取到旧素材。本轮清理只影响包含这些改动的新发行版本，既有远端提交不会自动变化。

## 使用 Live2D 的用户

1. 从 Live2D 官方渠道取得 SDK/模型，阅读适用的运行时协议、Free Material License 和具体角色条款。不要从不明镜像复制素材。
2. 本机开发预览时，将依法取得的 Core 放到 `frontend/public/vendor/live2dcubismcore.min.js`，模型放到既有的 `assets/live2d/...` 路径；这些路径受 Git 忽略规则保护。
3. 本体保留旧角色档案中的模型 ID 兼容能力，未附带模型的全新安装不能凭 ID 自动得到模型。
4. 需要发布带 Live2D 的应用时，在自己的发行流程里单独处理 SDK、模型、版权声明和授权，默认框架构建不会替你打包这些文件。

Live2D 的素材本体再分发、随作品使用/分发、角色设计修改，以及 SDK 发布许可是不同层次的问题。Hiyori Momose 有设计修改限制，不能把通用代码的修改权套用到角色上。收入门槛也不能代替对适用协议、主体及发布方式的核对。

## 可选语音

基础依赖不安装 Piper；用户选择完整本地语音后才安装。当前锁定的 `piper-tts` 1.8.0 元数据为 GPL-3.0-or-later。GPL 允许商用，实际义务取决于修改、组合及分发方式，不应概括成“装了就把整个项目变成 GPL”。

默认华燕音色的上游 MODEL_CARD 将数据集许可写为 Unknown。本体不会据此承诺音色的商用或再分发权，安装前会显示这项提示。实际商业发行应换成授权明确的音色，或取得相应授权。仅改用在线朗读客户端，也仍需检查服务使用条件。

## Apache 常见误解

- `LICENSE` 末尾的 `[yyyy] [name of copyright owner]` 是官方附录示例，保留许可证原文是正常做法。本项目另用 `NOTICE` 记载原创贡献者声明，不改官方条文。
- Apache-2.0 不授予一般的商标许可，但保留来源声明、惯常描述项目来源有明确例外，不能说产品中“绝对不能出现 Shionarium”。不要冒充官方或暗示未经授权的背书。
- Apache-2.0 下应按条款保留许可证、适用声明和修改说明；本项目新增的 NOTICE 随再分发按适用条款保留。

完整资源记录见 [`assets/LICENSE.md`](../../assets/LICENSE.md)；组件边界见 [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md)。这些文件不替代具体产品的许可核对，也没有声称已完成所有传递依赖审计。
