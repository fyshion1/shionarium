# 统一模型连接

聊天、附件看图、视频问答、画廊描述、记忆整理与未单独覆盖的插件，默认都从 **设置 → 模型连接** 读取同一份配置。

## 优先级

1. 已在网页保存：本地 SQLite 中的整份配置为准。留空的密钥或视觉模型不会从 `.env` 中补回旧值。
2. 从未保存：使用 `backend/.env` 的 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_CHAT`、`MODEL_VISION` 作为首次引导；可选 `VISION_BASE_URL`、`VISION_API_KEY` 指定独立视觉服务。
3. 两处都未配置：明确提示配置，框架不内置维护者账号或模型。

网页保存会即时影响后续请求，无需再改 `.env` 或重启后端；已在生成中的请求仍使用发起时的参数。环境文件只在未保存网页配置时引导，修改环境需重启。不会自动迁移、覆盖或打印用户已有密钥。

功能明确保存的独立覆盖仍生效，这是同一套配置的覆盖层。生图、语音合成/识别和 Embedding 使用不同接口或模型，按需单独配置，不会假设文字模型支持这些能力。

## 视觉与密钥

只有文字模型时可将视觉模型留空；看图接口会提示另配视觉模型，不自动把文字模型当成视觉模型。同一家支持多模态的服务可填写相同模型名，前提是该模型确实支持图片输入。

视觉地址留空则复用文字地址；同地址可复用文字密钥。视觉地址与文字地址不同时，应填写对应密钥，不会自动将文字服务的密钥发到另一家。

## 旧版本配置

旧浏览器 `xiaotangren.config` 中的地址、密钥、普通/无审查模型字段不再读取。该浏览器设置仅保留提示词通道偏好；切换提示词通道不会切换模型连接。现有浏览器中旧值可能仍占用存储，但不会作为模型来源使用。

此前版本只统一了聊天页，附件、画廊、个人资料和记忆的部分调用仍使用环境或旧浏览器字段，README 也误称两者独立。本轮统一了这些默认路径，保留旧 API 兼容与明确的单次调用/功能覆盖，不要求新用户重复填两套默认配置。
